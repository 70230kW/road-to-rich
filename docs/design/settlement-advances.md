# 立て替えを含む精算

基準: origin/main `d597069cab5dd0b6eca56acaaf6a0e3f35bef76f`（2026-11-28、PR #107後）。

## 依頼と受け入れ条件

- 通常の最終精算に「払えない人がいた場合」を追加し、その操作から専用画面へ進む。
- 各参加者の当日の支払額・受取額を入力し、通常の精算との差から返済元・返済先・金額を自動計算する。
- 別の人が多く支払う立て替えと、勝った人が受け取りを減らす立て替えの両方に対応（ユーザー確認済み）。
- 一部支払い、複数の不足者・立替者、3人/4人以上、場代・チップを扱う。端数や不足金を誰かへ黙って押し付けない。
- 金額が釣り合わない場合は不足/余りを表示し、保存を止める。実送金ではなく、支払い状況と返済関係の記録を行う。
- 精算と一緒に履歴へ保存し、履歴で返済待ちと返済記録を確認できる。通常の精算と過去のデータはそのまま使える。
- 順位・収支・段位は従来の対局結果を使い、現金の未回収や立て替えで変更しない。

## 金額の定義

当日の実収支 = 受取額 − 支払額（場代を含む、1円単位）。各人の返済請求額 = 従来の場代込み精算額 − 当日の実収支。正なら立替側、負なら後日返す側。全員の請求額合計が0のときだけ、未払側と立替側をIDの安定順で対応付ける。同じ入力なら同じ返済先になる。複数候補がある場合は自動配分であることを表示する。

場代の均等割は既存の切り上げを維持する。支払合計−受取合計が、全員の場代負担合計と一致することを確認する。場代の実費との差（端数調整）は専用画面に明記する。ゲーム・チップの収支が釣り合わない記録には自動配分を行わない。

## 保存と整合性

DayRecordに任意のpaymentを追加（version、cash、names、repayments）。返済関係はcashと元のsettlementから再計算。名前は記録時点の控えを残す。返済は受渡し確認後に履歴へ記録し、同じ返済操作の再試行・同時更新・過払いを防ぐ。従来の認証/ルーム共有方式は維持する。

履歴編集ではpaymentを保持し、既存の返済記録を消したり、別の債権へ移し替えたりしない。別端末で返済が進んでいた場合は古い画面からの上書きを止める。メモ・投票は支払い情報に影響させない。

精算は履歴への保存と当日データのクリアを同じFirestoreトランザクションで確定する。操作IDを使って再試行を重複保存せず、対局が追加・変更されていた場合は古い精算によるクリアを拒否する。返済記録もトランザクション内で最新の残額を検証する。[Firestoreのトランザクション仕様](https://firebase.google.com/docs/firestore/manage-data/transactions)に従い、読み取りをすべて書き込みより前に行う。

## Standards

独立レビューで未保存の支払い入力が内部の「戻る」で破棄される点、返済額エラーの読み上げと入力との関連付け、返済ボタンのdisabled/hover不足を指摘。確認付きで戻る処理、関連付けたエラー通知、状態ごとの表示を追加した。名前解決の重複という判断的指摘も共通関数へ整理した。

## Spec

独立レビューで記録当時の雀士名の上書きと同時返済テストの不足を指摘。名前は保存時の控えを優先し、重なった2つの返済とトランザクションの再試行をテストに追加した。通常精算、両方の立て替え、戦績との分離には欠落の指摘なし。

初回指摘件数: Standards 4件、Spec 2件。`039654f` でそれぞれ独立した再レビューを実施し、両軸とも指摘解消・追加指摘なしを確認。実表示と本番サービスの検証制約は上記のとおり。
