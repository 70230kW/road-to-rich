# Codexへの実装指示

リポジトリ `70230kW/road-to-rich` の「じゃんかね」のホームに、承認済み試作と同じ3D麻雀牌メニューを実装してください。提案だけで終わらず、既存アプリへの組み込みと動作確認まで進めてください。

## 最初に読むもの

- リポジトリの `AGENTS.md`、`package.json`、既存ホームと画面遷移の実装。
- `docs/design/jankane-home/README.md`
- `docs/design/jankane-home/reference/jankane-looping-tiles.html`（見た目と動きの基準）
- 同じ `reference/` 内の `prototype-script.js` と `prototype.css`（HTMLから抽出した読みやすいソース）
- `docs/design/jankane-home/assets/` の4枚の原画。

資料が別の場所にある場合は実際の場所を探してください。過去のチャットやこちらの作業環境のパスを参照できる前提では進めないでください。

## 1. ホームの見た目と動き

- 黒・チャコール・落ち着いたゴールドを基調に、試作の構図、余白、牌の質感を再現する。
- 1メニューに1枚の牌を対応させ、選択中の1枚が大きく明るく手前に出る。
- メニューと牌の対応は以下で固定する。
  - 01 順位表：赤伍萬 `red-five-man.png`
  - 02 対局入力：發 `green-dragon.png`
  - 03 ダッシュボード：七筒 `seven-circles.png`
  - 04 段位：一索 `one-bamboo.png`
- 使用する柄は同梱の原画。字体や鳥の形を描き直したり、別の牌画像に置き換えたりしない。原画の縦横比を保つ。
- 牌は角に丸みがあり、厚みのある白い本体と、緑で統一した背面を持つ。印字部分は浅くへこんだ形状にし、斜めから見たときに縁と陰影が分かるようにする。試作の実メッシュと法線処理を引き継ぐ。
- 奥へ移動する牌は、奥行きに応じて連続的に暗くなる。一定距離で突然非表示にしない。手前に戻れば再び明るくなる。
- 01→02→03→04→01、および逆方向に循環する。04→01でも移動方向を巻き戻さず、同じ軌道で動きをつなぐ。

## 2. 操作と既存画面への接続

- 横スワイプ、マウスドラッグ、左右ボタン、左右キー、メニュー名のクリックでフォーカスを切り替える。
- 指を離すと最寄りの牌へ自然に吸着する。メニュー名を直接選ぶときは近い方向から移動する。
- フォーカスの切り替えだけでは画面遷移しない。選択中の牌のタップ、または「順位表を開く」のような選択内容に合うボタンで、対応する既存画面を開く。開くボタンはキーボードでも操作できること。
- ドラッグ直後のクリックを誤って画面遷移として処理しない。
- 順位表・対局入力・ダッシュボード・段位は、既存のタブ切替や遷移関数につなぐ。特に対局入力は既存の入力・保存・再開フローを利用する。
- ホームへ戻ったときは直前に選んでいたメニューを復元する。
- 現行ホームのリーグ選択、ユーザー選択、対局中の表示・再開など、必要な導線も使える構成にする。入力中の順位確認など、既存の操作を維持する。

## 3. 実装品質

- 現在のReact/TypeScript構成に合わせてコンポーネント化する。試作のHTMLをiframeで表示して終わりにはしない。
- 試作のThree.js処理を参考に、リポジトリで管理する依存関係・画像ファイルとして組み込む。既存の3D基盤があれば優先して使う。
- 3D関連は必要時に読み込み、毎フレームのReact再描画、不要な常時描画、画面を離れた後の描画やGPUリソースの残留を避ける。
- スマホで縦スクロールを妨げず、牌と文字が見切れず、ボタンを押しやすい状態にする。
- `prefers-reduced-motion` とWebGLの利用不可・読み込み失敗に対応し、どちらの場合も4メニューへ移動できるようにする。
- 認証、Firebase接続、選手・対局データ、順位・収支・段位の計算は既存のものを継続利用する。今回の変更はホームと必要なナビゲーションに絞る。

## 4. 完了前に確認すること

- 4種類の原画、印字のへこみ、1枚へのフォーカス、奥行きに応じた暗さ。
- 04→01、01→04、複数周、途中で逆方向へ操作した場合の連続性。
- スワイプ後の誤遷移がなく、決定操作では4つの正しい既存画面が開くこと。
- 対局入力の既存フローと、ホームに戻ったときの選択状態。
- 320px、390px、768px、1024px程度の幅での表示と操作。
- 動きを減らす設定と3Dが使えない場合の代替表示。
- リポジトリに用意されている型チェック、ビルド、関連するテスト。

最後に、変更点、変更ファイル、実行した確認と結果、未確認事項を報告してください。実行できなかった検査は明記してください。既存の開発・PR運用があれば、それに従ってレビューできる状態にまとめてください。
