# じゃんかね：3D麻雀牌ホームの実装引き継ぎ

この資料は、2026年10月29日にチャットで確認した最終試作を、`70230kW/road-to-rich` の既存アプリへ組み込むためのものです。試作はホームの選択表現までを実装しており、業務画面への遷移と実データとの接続は本体への統合時に行います。

## 配置と使い方

ZIP内の `jankane-home/` フォルダを、Codexが編集するリポジトリの `docs/design/` の下に置いてください。結果として、このファイルの場所は `docs/design/jankane-home/README.md` になります。GitHub上のリポジトリをCodexの作業元にする場合は、資料もその作業元で読める状態にします。

`CODEX_PROMPT.md` の内容をCodexへ渡してください。資料を別のディレクトリへ置いた場合は、指示文の参照先も実際の場所に合わせます。

## 承認済みの仕様

### 対応関係

| 番号 | メニュー | フォーカスする牌 |
| --- | --- | --- |
| 01 | 順位表 | 赤伍萬 |
| 02 | 対局入力 | 發 |
| 03 | ダッシュボード | 七筒 |
| 04 | 段位 | 一索 |

1つのメニューに対して1つの牌を手前に大きく表示します。原画の字形、筒子の配置、鳥の形、配色、縦横比を保ってください。原画の背景や牌の外枠は、試作と同じ素材処理で本体へなじませます。4枚とも背面は緑で統一します。

### 奥行きと循環

最終試作の `pose(index, position)` を基準にします。4枚は閉じた軌道を移動し、奥ほど暗くなります。手前の牌による自然な遮蔽はありますが、距離による `visible = false` の切り替えはありません。

- `position` と `target` は0〜3に制限せず、連続した位置として扱う。
- 表示するメニュー番号だけを正の剰余で0〜3へ戻す。
- 角度から `sin` / `cos` で位置と奥行きを求める。
- 奥行きから、素材色・環境反射・ハイライトの強さを連続的に変える。
- 色は毎回、保存した基準色から計算し、現在色への累積乗算をしない。
- 線形座標を剰余で反対側へ飛ばす方法や、04から01への大きな巻き戻しを使わない。
- 直接メニューを指定したときは、現在の連続位置に最も近い同じメニュー位置を目的地にする。

試作の主な値は、軌道の横方向2.18、奥行き4.1、奥へ持ち上がる量0.85です。明るさ係数は `0.025 + 0.975 * exp(-5 * depth)` です。これらは最終試作に合わせるための初期値で、物理寸法や実測照度を表す値ではありません。

### 牌の立体形状

`createEngravedTile`、`prepareArt`、法線生成処理を参照してください。試作は、印字のマスクから表面頂点を浅く押し下げ、同じマスク由来の法線で細かな縁の陰影を補っています。凹み深さは試作のローカル座標で `0.014` です。

本体は角を丸めた白い樹脂の形状、背面は緑です。通常の平面カードに絵を貼るだけでは、今回の質感の要件を満たしません。移植で法線を二重に強めたり、表面と本体の境界に隙間・ちらつきが出たりしないよう、最終試作の形状処理を基準にしてください。

## 既存アプリへの統合

### 読み取りの入口

過去に確認した構成には `src/App.tsx` と `src/components/home/LeagueHomeSection.tsx` があり、ホームから既存画面へ移動するコールバックがありました。これらは調査の入口です。現在のリポジトリの状態を確認し、実際に存在するコンポーネントと遷移方法に合わせてください。存在しないルート名を推測して実装しないでください。

今回の対象はホームのメニュー体験と、それを動かすために必要なナビゲーションです。順位表、対局入力、ダッシュボード、段位の画面本体と計算処理は継続利用します。ホームに存在するリーグ・ユーザーの選択や対局中の再開などの機能も、アクセスできる形で配置します。

### 選択と決定

試作ではスワイプやメニュー名クリックが「フォーカス選択」です。実アプリでは別途、選択中の牌のタップと、選択名に合う「○○を開く」ボタンを設け、決定したときに既存画面へ遷移します。スワイプ終了直後のクリックを誤検出して遷移しないよう、移動量や操作状態で区別してください。

対局入力の起動は、既存の対局会・参加者・入力状態・権限を扱う入口へ接続します。保存済みデータや進行中の入力を破棄する別フォームは作らないでください。ホームへ戻った際の選択メニューも保持します。

### Reactへの移植

- UIの構造、選択状態、画面遷移は既存のReact/TypeScript構成に合わせる。
- 描画中の連続値は参照等で管理し、全体を毎フレーム再レンダリングしない。
- 試作のCDNインポートとBase64埋め込みは、アプリの依存関係と画像アセットへ置き換える。
- 試作で使ったThree.jsは `0.180.0`。導入時は現在の依存関係との整合性を確認する。
- セットアップとクリーンアップはReactのライフサイクルに合わせる。DOMを監視する試作の `MutationObserver` をそのまま本番の解放手段にしない。
- `requestAnimationFrame`、イベント、メディアクエリのリスナー、`ResizeObserver`、renderer、geometry、material、texture、環境マップを適切に停止・解放する。
- 初期化後の非同期処理がアンマウント済みの画面に描画しないようにする。
- 低い描画頻度でもアニメーションが必要以上に長引かないよう、時間刻みと補間を調整する。最終試作の軌道と印象を維持しつつ、実機の負荷に合わせる。
- 縦方向のページ操作を守り、キーボード操作と44px程度のタップ領域を確保する。
- 3Dが読み込めない場合でも、原画を使った代替表示と開くボタンから全メニューへ移動できるようにする。

## 試作で確認した範囲と統合時の確認

最終試作では、実際のWebGL表示、PCとスマホ幅の構図、04→01・01→04、複数周、境界をまたぐドラッグ、動きを減らす設定を確認しています。閉じた軌道の4周期一致と、奥行きによる明るさ係数の単調減少も数値確認しました。

試作のブラウザ検証にはソフトウェア描画を使用したため、実スマホのフレームレートを保証する測定ではありません。実アプリへの移植後は、通常描画での操作感と負荷を確認してください。実際の業務画面への遷移、認証、入力保存、ホームへの復帰は、統合後に改めて確認する対象です。

Codexの完了報告には、変更点、確認コマンドと結果、実際に確認できた画面・操作、未確認事項を含めてください。
