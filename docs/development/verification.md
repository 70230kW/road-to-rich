# 開発時の検証

変更した挙動が利用者にとって正しく動くことを確認する。コマンドの成功、ブラウザでの表示・操作、実機、本番サービスの結果は分けて記録する。

## コマンド

Node.jsの条件は `package.json` の `engines` を確認する。依存はlockfileを使って揃える。

| コマンド | 確認するもの |
| --- | --- |
| `npm run skills:check` | 導入した開発スキルと関連設定の整合性 |
| `npm run lint` | oxlintによる静的チェック |
| `npm test` | Vitest・Testing Libraryによる既存テスト |
| `npm run test:changelog` | アプデ履歴生成スクリプト |
| `npm run build` | TypeScriptチェックとVite本番ビルド |
| `npm run check` | 上記5項目を順に実行 |
| `git diff --check` | 差分の空白エラー |

作業中は関連するテストから実行し、PR前は一括確認を基準にする。実行できなかった項目、既存の警告、今回増えた失敗を区別する。テスト件数や所要時間はその回の出力を使い、過去の値を成功の証拠にしない。

## 変更に応じた検証

| 変更 | 最低限確認する対象 |
| --- | --- |
| スキル・開発ガイド | `skills:check`、参照先と適用範囲、代表的な依頼での読み込み |
| 精算・統計・段位 | 対応する純粋関数テスト、三麻／四麻、同点、境界値、場代・チップ、旧データ |
| 入力・保存フロー | 入力中・未入力・エラー・二重操作、単発／対局会／精算、下書きと再表示 |
| 画面・ナビ | TOP復帰、メニュー名の直接遷移、5タブ、個人／全体と表示期間 |
| 3D | 読み込み・成功・失敗、初回のちらつき、スワイプとタップ、回転、解除・資源破棄 |
| Firestore・ストア | 既存モックテスト、ルーム切替、購読、保存順序、エラー、旧データ互換性 |

回帰テストは再現する問題や失われると困る挙動を対象にする。低影響の文言変更や実装をそのまま写したテストを増やすための表ではない。

## 本番へ接続しないUI確認

```bash
npm run dev
```

表示されたローカルURLに以下のパスを付ける。実装は `qa/home-menu.tsx`。

| パス | 内容 |
| --- | --- |
| `/qa/home-menu.html?quality` | 集計・順位・複数画面の見た目を確認するfixture |
| `/qa/home-menu.html?flows` | 同日の複数対局会や、不参加の記録を含む導線確認用fixture |
| 上記に `&fallback` | WebGL非対応時の代替表示 |
| 上記に `&reduced` | JavaScript側のモーション軽減分岐 |

このfixtureは開発時だけ動き、`AppShell` を直接表示してstoreの操作を差し替える。半荘追加・削除、対局会開始・解除、精算はメモリ上で動き、再読込すると初期化される。他の保存操作は無効。本番Firebaseの認証・読み書きは行わない。

`&reduced` はCSSのメディアクエリ全体を変更しない。CSSを含めた確認はブラウザのメディアエミュレーションまたはOSの「視差効果を減らす」等を使う。

### 表示と操作の確認点

- 320／390／768／1024／1280px程度の幅で、長い名前、文字切れ、横はみ出し、ヘッダーと下部タブを確認する。変更していない画面まで毎回すべて撮影する必要はない。
- TOPには縦スクロールを出さない。牌のスワイプ後に誤遷移せず、メニュー名は1回のタップで開くこと、TOPへ戻ると選択が維持されることを確認する。
- 単発入力・対局会設定・精算を往復し、保存バーの位置、入力フォーカス、暫定順位、ソフトキーボードとの干渉を確認する。
- 3Dの初回表示、読込失敗、WebGL非対応、画面離脱・再表示、表彰台の開閉を確認する。操作ボタンは読込中にも使える状態を保つ。
- キーボード操作とフォーカス、空・読み込み・失敗・disabled・invalid・選択中の区別を確認する。
- モーション軽減、透過軽減、コントラスト、背景ぼかし非対応時の表示は変更箇所に応じて確認する。

ブラウザのデバイスエミュレーションはiPhone Safari実機と同一ではない。タッチ、ソフトキーボード、Safariの固定要素・背景ぼかし、実GPUの性能が問題になる変更は、実機確認の有無を明示する。

## 検証結果の書き方

記録するのは次の4点。

1. **対象**：要求された挙動、変更ファイル、比較した基準SHA。
2. **実行**：コマンドと成否、使用したfixture、ブラウザと幅、操作した経路。
3. **観測**：確認できた結果、今回の変更に起因する警告や失敗。
4. **未確認**：実機、本番Firebase、実GPUなど、今回実行していないものとその理由。

jsdomやCSSOMのテストは、実際の画面寸法・背景ぼかし・GPU描画を保証しない。fixtureでの保存成功は本番Firestoreの保存成功を意味しない。アクセスできない検証環境の結果を推測で補わない。
